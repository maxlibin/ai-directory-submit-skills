# Submit to AI Directories

## Overview

For each AI directory, drive a **headed** `agent-browser` session: open the submit page, **see** the form, fill what's there via element refs (`@e1`, `@e2`, ...), click submit, verify by screenshot and post-submit page text. When a wall appears (login / captcha / paid), classify and skip. When the user needs to log in personally, pause and ask them via chat — once they confirm, continue from the same page.

The skill is **interactive** — Claude drives the browser turn by turn. It is not an unattended bash batch. The earlier batch script (`run_batch.sh`) is now a **scout** pass that classifies walls without filling forms.

## Critical lessons (learned the hard way)

These are not optional. Ignoring them leads to silent failures that look like submissions but aren't.

0. **When a directory needs login, PAUSE and ask the user — do not skip silently.** A "login wall" is anything where the form isn't reachable without authentication: URL contains `login` / `signin` / `auth` / `register` / `sign-up`; OR the visible snapshot only shows email/password inputs and "Sign in with Google/GitHub/Email" buttons. When this happens:
   - Keep the browser window open (don't navigate away).
   - Tell the user in chat: _"Directory `<name>` needs me to sign in (URL: `<current_url>`). Please log in (e.g. Sign in with Google) in the browser window that's open, then reply 'continue' and I'll proceed."_
   - Wait for the user's reply.
   - When they say continue / done / proceed, re-snapshot the page (they may now be on a different URL — a dashboard, a wizard, or back on the submit page) and continue with the submission flow from there.
   - Only mark as `skipped: login-required` if the user explicitly says skip.
   This is the default behavior whenever Claude is driving the browser turn-by-turn. The bash script's `INTERACTIVE=1 STATE_FILE=…` mode supports the equivalent flow from a real terminal.
1. **Look at the form before filling.** Always run `agent-browser snapshot -i` first. Do not pre-guess label names from a hardcoded list — every directory uses different text. `find label "Tool Name" fill ...` succeeds on aitoolslist.io and silently does nothing on 80% of others.
2. **Fill via refs, not heuristics.** `fill @e3 "Banana Flow"` is deterministic. `find label "Tool Name" fill ...` exits 0 on success and non-zero on miss — and the miss is silent if you `|| true` it.
3. **Refs invalidate when the DOM changes.** After clicking a combobox, opening a dropdown, or expanding a section, re-snapshot before using any ref. Otherwise `@e60` may now match 7 elements (e.g. wrapped rich-text editor) and the fill will refuse to commit.
4. **Rich-text editors don't accept `@ref fill`.** Many forms use ProseMirror / TipTap / TinyMCE wrapped editors. The ref points to a wrapper that matches the editor's internal elements too. Use `agent-browser keyboard inserttext "..."` after clicking into the editor instead, or `eval` to set the contenteditable directly.
5. **Logo uploads are required by some directories** and need an actual local file path in `submission-info.json` (`logo_path`). Without it, those directories can't be completed.
6. **A submit URL ending up at Stripe/checkout = paid-only.** The form may pre-fill the user's email into a checkout — that is *not* a successful submission. See `references/submission-patterns.md` for the full pattern list.
7. **Confirmation is not always a URL change.** Tally shows "Thanks for completing this form!" in-place. Check the post-submit screenshot and page text, not just `get url`.
8. **macOS bash is 3.2.** Don't use `${var@Q}`, `[[ … ]]` with regex alternatives, or `mapfile`. The skill's scripts are 3.2-compatible.

## State files (in the user's working directory, not in the skill)

| File | Purpose |
|---|---|
| `submission-info.json` | The user's tool metadata. Must be filled in by hand from `assets/submission-info.template.json`. |
| `submission-history.json` | Append-only JSON array of every attempt. Source of truth for dedup and the HTML report. |
| `submission-report.html` | Generated by `scripts/render_report.py` from the history file. |
| `shots/<safe-name>.png` and `shots/<safe-name>_after.png` | Pre- and post-submit screenshots, referenced from the report by relative path. |

## Workflow

```
1. Collect info  →  2. Fetch list  →  3. (optional) Scout pass  →  4. Per-directory submission loop  →  5. Report
```

### 1. Collect submission info

**Preferred path: auto-scrape from the tool's URL, then have the user review.** If the user gives a URL and doesn't already have `submission-info.json`:

```bash
python3 scripts/scrape_metadata.py https://their-tool.com -o <workspace>/submission-info.json --download-logo
```

This pulls `name`, `tagline`, `short_description`, `long_description`, `pricing`, `logo_url`, social links from the site's HTML + OG/Twitter meta tags, and downloads the logo. Fields it can't infer (categories, email, sometimes logo_path) are written as `TODO:` strings.

**Then walk the user through the TODOs in chat.** Show them the scraped values, ask for the missing ones, write them back. Do not proceed until every `TODO:` is replaced.

If scraping isn't possible (the site is JS-only, blocked, or the user wants to enter data manually), fall back to copying `assets/submission-info.template.json` and asking for each field.

- **Required**: `name`, `url`, `tagline` (≤100 chars), `short_description` (≤200 chars), `long_description`, `categories[]`, `pricing` (Free / Freemium / Free Trial / Paid / Contact), `email`.
- **Often required**: `logo_path` (an actual local file). Many directories block submission without a logo upload.
- **Optional**: `twitter`, `linkedin`, `github`, `instagram`, `screenshot_url`.

**Never proceed with the template placeholders or `TODO:` strings** (`"Your Tool Name"`, `"TODO: contact email"`, etc.). Filling junk into real directories permanently associates the user's brand with that junk.

### 2. Fetch the directory list

```bash
python3 scripts/fetch_directories.py --format json > <workspace>/dirs.json
```

Flags: `--limit N`, `--section A` (single letter), `--raw` (dump README). The fetcher drops `github.com/...` entries (those need PRs, not forms). Default scope when the user doesn't specify: ask. Don't assume "all 150".

### 3. Scout pass (optional but recommended for large batches)

```bash
SCOUT_ONLY=1 bash scripts/run_batch.sh <workspace> 0 1
```

The scout pass walks every directory, finds the submit URL, detects walls (login / captcha / paid / no-submit-form), and records the outcome in `submission-history.json`. **It does not fill or submit forms.** Use it to triage which directories are even worth attempting before spending time on each.

Without `SCOUT_ONLY=1`, the script attempts a best-effort heuristic fill — only useful for the simplest standard forms (Tally embeds with `Tool Name` / `Website` / etc. labels). Most directories need the Claude-driven flow in step 4 instead.

### 4. Per-directory submission loop (Claude drives the browser)

For each directory not already handled (per `check_submitted.py`):

#### 4a. Dedup check

```bash
python3 scripts/check_submitted.py <workspace>/submission-history.json "$TOOL_URL" "$DIR_URL"
# exit 0 = already handled (skip); exit 1 = retry/attempt
```

Handled = `submitted` OR `skipped` with terminal reason (`paid-only`, `github-pr-only`, `email-only`). Retryable = `failed`, `unknown`, `skipped: login-required`, `skipped: captcha`, `skipped: no submit form found` (these may succeed next time with auth state, manual help, or a fresh look).

#### 4b. Resolve the submit URL

```bash
SUBMIT_URL=$(bash scripts/find_submit_link.sh "$DIR_URL" submitdir 2>/dev/null)
```

The script probes common submit paths (`/submit`, `/submit-tool`, `/add-tool`, …) with `curl`, then scans the homepage with `agent-browser` for "Submit", "List Your Tool", "Add", and similar link text. **Also accept variants like "List Your AI Agent"** — if the curl probe and homepage scan both miss, open the homepage and inspect the nav manually with `eval`:

```bash
agent-browser --session submitdir eval 'Array.from(document.querySelectorAll("a")).filter(a => /add|submit|list|post|register/i.test(a.textContent)).map(a => ({text: a.textContent.trim(), href: a.href}))'
```

If the result is a `/register` or `/sign-up` URL, treat it as login-required (see 4f).

#### 4c. Open the form (headed)

```bash
agent-browser --headed --session submitdir open "$SUBMIT_URL"
agent-browser --session submitdir wait --load networkidle
```

The headed flag is important: it makes the run visible to the user so they can watch, intervene on login walls, and verify the work as it happens.

#### 4d. Detect iframe-embedded forms

Many directories embed Tally / Typeform / Google Forms in an `<iframe>`. The default snapshot doesn't traverse iframes, so the form fields will look invisible. After opening, check:

```bash
IFRAME=$(agent-browser --session submitdir eval \
  'Array.from(document.querySelectorAll("iframe")).map(f => f.src).filter(s => /tally|typeform|fillout|paperform|airtable|google\.com\/forms/.test(s))[0] || ""' \
  | tr -d '"')
```

If non-empty, open the iframe `src` directly — the form fields will then appear at the top level. Verified working with Tally on aitoolslist.io.

#### 4e. Detect walls via URL

After `wait --load networkidle`, check the current URL:

| Pattern in URL | Reason | Action |
|---|---|---|
| `login`, `signin`, `auth/`, `/sign-up`, `/register` | login-required | go to 4f |
| `verify`, `captcha`, `challenge` | captcha | skip with reason `captcha` |
| `stripe.com`, `checkout.`, `paypal.com`, `gumroad.com`, `lemonsqueezy.com`, `/upgrade`, `/pricing`, `/plan`, `/billing` | paid-only | skip with reason `paid-only` (terminal — won't retry) |

#### 4f. Login wall — ask the user in chat

When the form is behind a login wall (URL contains login/signin/register, or the visible snapshot only shows "Sign in with Google / GitHub / Email" buttons):

1. **Tell the user clearly**: "Directory `<name>` needs me to sign in. Please log in (e.g. Sign in with Google) in the browser window that's open, then say 'continue' and I'll proceed."
2. Wait for the user's reply.
3. When they say done/continue/etc., re-snapshot the page and continue with the form fill at step 4g.
4. If the user says skip, record `skipped: login-required (user declined)` and move on.

The user must run Claude Code with a headed browser visible to them for this to work. (For pure unattended runs, `run_batch.sh` with `INTERACTIVE=1 STATE_FILE=...` from a real terminal supports the same pattern via stdin.)

#### 4g. Snapshot, fill, submit

```bash
agent-browser --session submitdir snapshot -i
```

Read the textbox / combobox / button refs that actually appear. **Map them to `submission-info.json` keys yourself** based on the visible label text — don't run through a fixed list.

```bash
# Fill via refs (deterministic). Re-snapshot after any combobox/option click.
agent-browser --session submitdir fill @e3 "$TOOL_NAME"
agent-browser --session submitdir fill @e4 "$TOOL_URL"
agent-browser --session submitdir click @e8        # opens dropdown
agent-browser --session submitdir snapshot -i      # refs may have shifted
agent-browser --session submitdir click @e15       # the desired option, by NEW ref
```

For rich-text editor fields (ProseMirror, TipTap, etc.) where `fill @ref` matches multiple elements, click into the editor by its ref then use keyboard:

```bash
agent-browser --session submitdir click @eEDITOR
agent-browser --session submitdir keyboard inserttext "$LONG_DESCRIPTION"
```

Screenshot the filled state, then click submit by its ref:

```bash
agent-browser --session submitdir screenshot --full "$WORKSPACE/shots/${SAFE_NAME}_filled.png"
agent-browser --session submitdir click @eSUBMIT   # use the exact ref from the snapshot
agent-browser --session submitdir wait --load networkidle
sleep 2
agent-browser --session submitdir screenshot --full "$WORKSPACE/shots/${SAFE_NAME}_after.png"
```

#### 4h. Verify the outcome

Do NOT trust URL change alone. Check **all** of:

- **URL**: `final=$(agent-browser --session submitdir get url)` — does it contain `thank`, `success`, `received`, `submitted`, `pending`, `confirm`, `complete`?
- **Page text**: `agent-browser --session submitdir get text body | head -c 2000` — does it contain `thanks for submitting`, `we received`, `under review`, `pending approval`?
- **Form disappearance**: re-snapshot and check whether the form fields are gone.
- **Paid-redirect**: if final URL matches the paid-only regex above, the directory is paid — classify as `skipped: paid-only`, not `submitted`.

Classify as `submitted` only when at least one positive signal is present *and* no paid-redirect occurred.

#### 4i. Append to history

After every attempt, append a record using `jq` to keep the file as a valid JSON array:

```bash
ENTRY=$(jq -nc \
  --arg tu "$TOOL_URL" --arg tn "$TOOL_NAME" \
  --arg dn "$DIR_NAME" --arg du "$DIR_URL" --arg su "$SUBMIT_URL" \
  --arg st "$STATUS" --arg rn "$REASON" \
  --arg sh "$SHOT" --arg fu "$FINAL_URL" \
  --arg at "$(date -u +%Y-%m-%dT%H:%M:%SZ)" \
  '{tool_url:$tu, tool_name:$tn, directory_name:$dn, directory_url:$du,
    submit_url:$su, status:$st, reason:$rn, screenshot:$sh,
    final_url:$fu, submitted_at:$at}')

[ -f "$HISTORY" ] || echo "[]" > "$HISTORY"
tmp=$(mktemp) && jq --argjson e "$ENTRY" '. += [$e]' "$HISTORY" > "$tmp" && mv "$tmp" "$HISTORY"
```

Required `status` values: `submitted` | `skipped` | `failed` | `unknown`.

### 5. Live dashboard (recommended — run alongside submissions)

**Primary: terminal live view.** Tell the user to open a second terminal tab and run:

```bash
python3 scripts/watch.py <workspace>
```

It uses the alt-screen so it doesn't pollute scrollback, shows a colored status header (submitted / skipped / failed / unknown counts + success rate + elapsed time), a "NOW" panel for the current step, and a table of recent attempts. Auto-refreshes when files change. Ctrl-C to exit.

**To make the "NOW" panel show what's currently happening**, after each meaningful step write `submission-status.json` to the workspace before doing the action:

```bash
jq -nc --arg d "$DIR_NAME" --arg s "opening submit page" --arg u "$SUBMIT_URL" \
       --arg at "$(date -u +%Y-%m-%dT%H:%M:%SZ)" \
  '{directory:$d, step:$s, url:$u, message:"", prompt:"", updated_at:$at}' \
  > "$WORKSPACE/submission-status.json"
```

When you need the user to do something (log in, solve a captcha), set `prompt`:

```bash
jq -nc --arg d "$DIR_NAME" --arg p "Please sign in with Google in the browser, then reply 'continue'." \
       --arg at "$(date -u +%Y-%m-%dT%H:%M:%SZ)" \
  '{directory:$d, step:"login wall", url:"", message:"", prompt:$p, updated_at:$at}' \
  > "$WORKSPACE/submission-status.json"
```

The `watch.py` dashboard renders `prompt` in a red "NEEDS YOU" banner so it's impossible to miss across tabs.

**Alternative: browser dashboard.** If the user prefers HTML in a browser:

```bash
python3 scripts/live_dashboard.py <workspace> --port 8765 --open
```

Same data, side-by-side source vs. screenshots, opens at `http://127.0.0.1:8765/`.

### 6. Render the static HTML report

After each directory (so the user can peek mid-run) and at the end:

```bash
python3 scripts/render_report.py <workspace>/submission-history.json --open
```

This writes `submission-report.html` next to the history file and opens it in the default browser. Self-contained HTML — sortable, filterable, search box, screenshot thumbnails with click-to-zoom.

Suggested chat summary line: `"Submitted to X / Y. Z skipped (paid/login/captcha), W failed, U unknown. Report: <workspace>/submission-report.html"`

## Important rules

- **Login walls = pause and ask, never silent-skip.** See critical lesson 0 above. The whole point of running headed is that the user can sign in personally for sites where Google login is required. Skipping is only the right call when the user explicitly says so.
- **Always headed.** Use `agent-browser --headed --session submitdir`. The user needs to see what's happening and be able to intervene on login walls.
- **One session.** Use the same `--session submitdir` name across all calls in a run. Close at the end.
- **Don't guess data.** If a field has no answer in `submission-info.json`, leave it blank (when allowed) or skip with reason `"missing data: <field>"`. Inventing categories, emails, or socials creates junk listings.
- **Don't re-submit.** Always run the dedup check first.
- **Pace requests.** A `wait --load networkidle` between directories is usually enough. Don't fire in parallel.
- **Stop on repeated walls.** If 3 directories in a row hit Cloudflare / captcha walls, the IP may be rate-limited — stop and tell the user.
- **GitHub-hosted "directories"** (awesome-* lists) are dropped by `fetch_directories.py` automatically. Those need PRs, not forms.

## Files

| File | Purpose |
|---|---|
| `scripts/scrape_metadata.py` | Auto-fills `submission-info.json` from a tool URL (title, descriptions, OG/Twitter meta, logo, social links, pricing hint). Leaves `TODO:` for what it can't infer. |
| `scripts/fetch_directories.py` | Fetches and parses the best-of-ai README into JSON/JSONL |
| `scripts/find_submit_link.sh` | Probes common submit paths; falls back to homepage link scan |
| `scripts/check_submitted.py` | Dedup: exits 0 if `(tool_url, directory_url)` is already handled (submitted or terminal-skipped) |
| `scripts/watch.py` | **Terminal live dashboard** — alt-screen ANSI, header counts, NOW panel with login/captcha prompts, recent table. Run in a second terminal tab. |

| `scripts/run_batch.sh` | Scout pass / batch runner. `SCOUT_ONLY=1` to only classify walls without filling. `HEADED=1` to show the browser. `INTERACTIVE=1 STATE_FILE=…` for terminal-based login pauses. |
| `assets/submission-info.template.json` | User-facing template for tool metadata |
| `references/submission-patterns.md` | Field mappings, what to skip, iframe-form handling, paid-only patterns, ref-invalidation lessons |

## Quick start

```bash
# 1. Auto-scrape metadata from the tool URL (user reviews TODOs after)
python3 scripts/scrape_metadata.py https://their-tool.com \
  -o /path/to/workspace/submission-info.json --download-logo

# 2. (User opens a second terminal tab and runs the live dashboard)
python3 scripts/watch.py /path/to/workspace

# 3. Sample directories
python3 scripts/fetch_directories.py --limit 3 --format json

# 4. Verify submission-info.json has no TODO placeholders left
python3 -c 'import json,sys; d=json.load(open(sys.argv[1]));
v=[k for k,v in d.items() if isinstance(v,str) and v.startswith("TODO")];
assert not v, f"still TODO: {v}"; assert d["name"]!="Your Tool Name"; print("ok")' \
  /path/to/workspace/submission-info.json

# 5a. Optional: scout pass to classify walls
SCOUT_ONLY=1 bash scripts/run_batch.sh /path/to/workspace 0 1

# 5b. Recommended: Claude drives each form interactively, writing
#     submission-status.json between steps so the watcher shows live progress.

# 6. After the run, optionally render the static HTML report
python3 scripts/render_report.py /path/to/workspace/submission-history.json --open
```
